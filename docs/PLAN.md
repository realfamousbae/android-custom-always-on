# StandBy для Android (Galaxy S24 Ultra): план проекта

Статус: план утверждён 2026-11-05. Этап 0 выполнен. Этап 1 (spike) пройден на S24 Ultra
(Android 17 / One UI 9) 2026-11-05: ключевая связка работает, запасные пути не понадобились.
2026-11-05 требования изменены: режим работает и без зарядки, включается сам после
погасания экрана, есть автояркость; сборки — в публичном репозитории через GitHub Actions
(см. «Статус MVP» в разделе 4). Этот файл — единственный источник истины по проекту;
по ходу работы обновлять разделы «Этапы», «Статус MVP», «Журнал решений» и «Риски».

## 1. Контекст и цель

Нужен аналог iOS StandBy для Android: когда телефон стоит на боку (горизонтально),
на зарядке или без неё, вместо обычного AOD/заблокированного экрана показывается собственный
полноэкранный «прикроватный» режим с минимальным набором виджетов. Обязателен
ночной режим «красный свет». Первое устройство: Samsung Galaxy S24 Ultra
(фактически на 2026-11-05: One UI 9, Android 17 / API 37); архитектуру закладываем так, чтобы потом унифицировать
под другие Android-устройства (Pixel и т. п.).

Решения, принятые с пользователем:

## 2. Как это устроено на уровне системы

### 2.1 Почему не «настоящий» AOD

Системный Always On Display Samsung нельзя заменить без root. Поэтому режим
реализуется как обычное приложение, которое в нужный момент выводит свою
полноэкранную Activity поверх экрана блокировки и держит экран включённым
на низкой яркости. Так работает, например, открытый аналог nightstand.

### 2.2 Два возможных механизма запуска и выбор

**A. Собственный foreground-сервис + Activity поверх блокировки (основной путь).**
Сервис следит за зарядкой, ориентацией и состоянием экрана, и сам запускает Activity.
Плюсы: мгновенная реакция на поворот и подключение зарядки, полный контроль условий.
Минусы: нужны разрешения «Поверх других окон» и исключение из оптимизации батареи;
Samsung может усыплять сервис.

**B. DreamService («Заставка» в Настройки → Дисплей → Заставка, «Во время зарядки»).**
Системно-одобренный путь, на One UI присутствует. Минусы: заставка стартует только
когда экран гаснет по таймауту, не реагирует на поворот уже спящего телефона, не
знает про ориентацию (её пришлось бы проверять внутри и тут же выходить).

**Решение:** основной механизм A. DreamService добавить позже как второй вход для
унификации (Pixel, устройства, где фоновый запуск заблокирован), используя тот же
UI-слой. Официальная документация Android (Background Activity Launch) подтверждает:
приложение с предоставленным пользователем `SYSTEM_ALERT_WINDOW` может запускать
Activity из фона; это исключение действует и на Android 15/16.

### 2.3 Условия показа (TriggerEngine)

Решение принимает чистый редьюсер `TriggerEngine.reduce(state, event, nowMs, settings)` в
`:core` (без Android, время передаётся явно), служба только собирает события и исполняет
эффекты (`SetSensorActive`, `HoldWakeLock`, `ScheduleTick`, `Show`, `Hide`). Фазы:
`Idle` → `Armed` (экран погас, ждём положение) → `Showing`; отдельно флаг `suppressed`.

**Вход — только по фронтам**, а не по состоянию «экран горит на блокировке» (иначе режим
выскакивает, когда пытаешься разблокировать телефон на подставке):
- экран погас (`SCREEN_OFF`: кнопкой или по таймауту) — главный сценарий «попользовались и
  оставили»;
- подключили зарядку при погашенном экране;
- сработал wake-up датчик движения `Tilt Detector` при погашенном экране (без зарядки
  поставили уже погашенный телефон на подставку).

После фронта — `Armed`: включаем акселерометр. На зарядке ждём без ограничения по времени,
без зарядки — окно пробы 10 с, затем датчик и wake lock отключаются.

**Показ**, когда одновременно:
1. **Стоит на боку** непрерывно 1.5 с — угол между осью X устройства и вектором силы тяжести
   меньше порога (по умолчанию 45°, т. е. `|gx| > ~6.9 м/с²`). Отдельная проверка «не плашмя»
   не нужна: плашмя `gx ≈ 0`, в портрете `gy ≈ 9.8`. Обычные подставки наклонены на 20–35°;
   в настройках — живой индикатор угла для калибровки.
2. **Питание позволяет** — заряжается, либо (если не включено «Только на зарядке») заряд не
   ниже порога.
3. **Нет запрета** (`suppressed`) после закрытия режима пользователем.

**Скрытие:** угол больше порога + 10° непрерывно 2 с (взяли в руки); без зарядки заряд упал
ниже порога или включено «Только на зарядке»; разблокировали телефон (`USER_PRESENT`);
закрыли жестом / кнопкой питания.

**Возврат после закрытия** (изменено 2026-11-05 по отзыву с S24 Ultra): если телефон не
разблокировали и оставили на подставке, режим возвращается после погасания экрана.
- Закрыли тапом — без запрета: пока экран горит, режим и так не всплывает; экран погас
  по таймауту → снова Armed → режим.
- Погасили режим кнопкой питания — запрет **до следующего включения экрана**; пока он
  действует, ожидание не взводится (ни датчика, ни wake lock на всю ночь). Включили экран
  и оставили → погас → режим. Запрет снимают также разблокировка и смена зарядки.
- Activity может уйти раньше, чем дойдёт `SCREEN_OFF`; поэтому служба добавляет к
  `UserExit` текущее `isInteractive`, и выход при погашенном экране считается кнопкой.

Ручной показ (кнопка теста, позже плитка) обходит условия и закрывается только пользователем.

Датчик: wake-up акселерометра на S24 Ultra нет (spike), поэтому пока `Armed` при погашенном
экране — `PARTIAL_WAKE_LOCK` (не по ссылкам, с таймаутом 10 мин и перевзводом каждые 5 мин,
отпускается эффектом). При показанном режиме экран горит, wake lock не нужен.

### 2.4 Поддержание сервиса живым (Samsung)

- Foreground-сервис типа `specialUse` (без таймаутов Android 15), тихое уведомление
  с минимальным приоритетом. Стартует при загрузке (`BOOT_COMPLETED`), при открытии
  приложения и из фонового Worker'а.
- `ACTION_POWER_CONNECTED`, `SCREEN_OFF` и др. **нельзя** ловить manifest-receiver'ом
  (implicit broadcasts с Android 8). Поэтому receiver'ы регистрируются в сервисе
  динамически, а страховка — периодическая WorkManager-задача (15 мин, без условий, т. к.
  режим работает и без зарядки), которая поднимает сервис, если тот был убит.
- Исключение из оптимизации батареи (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) —
  по документации входит в список исключений, разрешающих старт FGS из фона, и
  защищает от усыпления. Это утверждение проверяется в spike (этап 1, п. 7); если
  не сработает — запасные пути: (а) перед стартом сервиса показать невидимое окно
  1×1 `TYPE_APPLICATION_OVERLAY` (есть право «Поверх других окон»), дождаться
  `getWindowVisibility() == VISIBLE`, запустить FGS, убрать окно — документированный
  для Android 15 маршрут; (б) точный будильник (`SCHEDULE_EXACT_ALARM`, для sideload
  доступен) — ещё одно документированное исключение. Плюс ручные шаги на One UI:
  Батарея → «Без ограничений», добавить в «Никогда не усыплять», выключить «Переводить
  неиспользуемые приложения в спящий режим» для этого приложения. Всё это — в мастере
  разрешений внутри приложения с кнопками-переходами в нужные экраны настроек.

### 2.5 Activity режима

- `setShowWhenLocked(true)`, `setTurnScreenOn(true)`, `FLAG_KEEP_SCREEN_ON`,
  иммерсивный режим (скрыты системные панели), `screenOrientation=sensorLandscape`,
  `launchMode=singleInstance`, `excludeFromRecents`, `noHistory`, отдельный `taskAffinity`.
- Яркость — через `WindowManager.LayoutParams.screenBrightness` независимо от системной,
  автоматически по датчику освещённости: `AutoBrightness` в `:core` — логарифмическая кривая
  (≤ 1 лк → 0.01, ≥ 1000 лк → 0.6), экспоненциальное сглаживание (τ = 3 с) в лог-шкале,
  ограничение скорости 0.25/с, мёртвая зона. Датчик отдаёт события только при изменении,
  поэтому `BrightnessController` подкручивает значение по таймеру 200 мс.
- Выход: `finish()` → возвращается экран блокировки/AOD, экран гаснет по системному
  таймауту блокировки. Опция v1.1: Device Admin `lockNow()` для мгновенного гашения
  (настройка, по умолчанию выключена, т. к. Device Admin — заметное разрешение).
- Сканер отпечатка под экраном в режиме не работает (экран блокировки не виден);
  поворот в портрет закрывает режим и возвращает блокировку — это и есть сценарий
  «взял телефон в руки».

### 2.6 Защита OLED от выгорания

Чёрный фон, нет больших ярких площадей, смещение всего слоя на несколько пикселей
каждые 60 с, низкая яркость по умолчанию, «глубокая ночь» (ещё ниже яркость) через
N минут без касаний, настраиваемое авто-выключение через X часов.

### 2.7 Ночной режим «красный свет»

- Отдельная тема: единственный оттенок — красный (пример `#FF3B1F`) на чёрном,
  без синего и зелёного каналов; низкая яркость. Для контента, который темой не
  управляется (иконки погоды, обложки альбомов), поверх накладывается `ColorMatrix`
  фильтр, обнуляющий G и B.
- Режимы включения (настройка): `Off` / `Manual` / `Schedule` / `Sensor` /
  `Schedule AND Sensor` / `Schedule OR Sensor`.
  - Расписание: фиксированный интервал (по умолчанию 22:00–07:00) или закат–рассвет
    (вычисляется локально по координатам, без сети: стандартный алгоритм NOAA).
  - Датчик: `TYPE_LIGHT`, порог в люксах с гистерезисом и задержкой (например
    `< 5 lx` 30 с → ночь, `> 15 lx` 30 с → день).
  - Ручной тумблер: долгое нажатие → быстрое меню, плюс плитка в шторке (TileService).

### 2.8 Виджеты и раскладка

Экран делится на страницы (горизонтальный пейджер), каждая страница — один
«полноэкранный» виджет или два слота (левый/правый), как в iOS. Пользователь в
настройках выбирает виджет для каждого слота. Раскладка хранится как JSON в DataStore.

Сейчас (2026-11-05) реализованы две раскладки: «только часы» и «часы | системный виджет»
(`ScreenLayout` в `:core`, `StandbyWidgetHost` поверх `AppWidgetHost`; выбор виджета —
свой список в настройках, затем системный диалог привязки и экран настройки виджета).
Пейджер и свои виджеты — дальше по этапам.

Баннеры уведомлений (2026-11-05): `StandbyNotificationListener` → правила в `:core`
(`NotificationFilter`, `LockscreenPrivacy`, `BannerDedupe`) → `NotificationBus` →
`NotificationBannerHost` (один `Animatable`: `rotationX` вокруг верхнего края,
`translationY`, масштаб, прозрачность; 5 с на экране).

Контракт виджета (`StandbyWidget`): `id`, `title`, требуемые разрешения, `Flow<State>`
данных, composable-рендер для размеров `Full` и `Half`, поддержка темы (день/ночь).
Через этот же контракт позже подключится `AppWidgetHost` (системные виджеты как ещё
один тип виджета, накрытый красным фильтром в ночном режиме).

| Виджет | Данные | Разрешения |
|---|---|---|
| Часы + дата | системное время, 12/24 ч по системе, цифровые/аналоговые, секунды опц. | нет |
| Батарея | %, тип зарядки, мощность (`BATTERY_PROPERTY_CURRENT_NOW`, если Samsung отдаёт), время до 100% (`computeChargeTimeRemaining`) | нет |
| Погода | Open-Meteo (бесплатно, без ключа): сейчас + прогноз на день; координаты из геолокации (coarse) или заданы вручную; обновление раз в 30–60 мин и только пока режим активен; кэш | `INTERNET`, опц. `ACCESS_COARSE_LOCATION` |
| Календарь | ближайшие события сегодня/завтра через `CalendarContract`, фильтр календарей | `READ_CALENDAR` |
| Сейчас играет | `NotificationListenerService` → `MediaSessionManager` → `MediaController`: трек, исполнитель, обложка, play/pause/next | доступ к уведомлениям |
| Уведомления | счётчик и иконки активных уведомлений из того же listener'а; только чтение | доступ к уведомлениям |

Все разрешения, кроме базовых, опциональны: виджет без разрешения показывает
подсказку «дать доступ» вместо данных.

### 2.9 Жесты в режиме

- Свайп влево/вправо — страницы.
- Тап — «подсмотреть»: яркость выше на 10 с.
- Долгое нажатие — быстрое меню: Выйти / Ночной режим вкл-выкл / Не показывать до
  отключения зарядки / Настройки.
- Свайп вниз двумя пальцами — выход (альтернатива меню).

## 3. Технологии и структура проекта

- Kotlin 2.x, Jetpack Compose + Material 3 (своя тема), Coroutines/Flow,
  DataStore (Preferences) + kotlinx.serialization, WorkManager, Ktor или OkHttp +
  kotlinx.serialization для Open-Meteo. Без DI-фреймворка (ручной `AppGraph`), чтобы
  не усложнять.
- AGP 9.5 (Kotlin встроен в Android-плагин), Kotlin 2.4, Gradle 9.8 (wrapper), Gradle Kotlin DSL,
  version catalog `gradle/libs.versions.toml`, JDK 21, `minSdk 31`, `targetSdk 37`, `compileSdk 37`.
- Два модуля: `:core` — чистый Kotlin/JVM без Android (логика решений и модели, unit-тесты),
  `:app` — всё Android-зависимое. Пакет `com.realfamousbae.standby.dock`. Ниже — целевая
  раскладка `:app`; файлы из `core/` физически лежат в модуле `:core`
  (`core/src/main/kotlin/com/realfamousbae/standby/dock/core/...`):

```
app/src/main/java/com/realfamousbae/standby/dock/
  App.kt                      // Application: AppGraph, каналы уведомлений

    trigger/OrientationClassifier.kt

    night/SolarTimes.kt       // закат–рассвет (NOAA)

  standby/
    StandbyActivity.kt        // showWhenLocked, turnScreenOn, яркость, выход
    StandbyScreen.kt          // пейджер, слоты, жесты, быстрое меню
```

Разрешения в манифесте: `SYSTEM_ALERT_WINDOW`, `FOREGROUND_SERVICE`,

`READ_CALENDAR`, `ACCESS_COARSE_LOCATION`, `BIND_NOTIFICATION_LISTENER_SERVICE`,
`BIND_DEVICE_ADMIN` (v1.1), `USE_FULL_SCREEN_INTENT` (запасной путь запуска, см. риски).

## 4. Этапы реализации

### Этап 0. Окружение (день 1) — выполнен 2026-11-05

1. `brew install --cask android-studio`, `brew install android-platform-tools` (adb).
2. В Android Studio: SDK Platform 35, Build-Tools, Emulator не обязателен (тестируем
   на устройстве).
3. На S24 Ultra: режим разработчика (7 нажатий на «Номер сборки»), отладка по USB и
   «Беспроводная отладка»; спарить `adb pair`, дальше `adb connect` по Wi-Fi.
4. Создать проект (Empty Compose Activity), `git init`, `.gitignore` для Android,
   положить `PLAN.md`, добавить `CLAUDE.md` с правилами проекта (язык, стиль, запрет
   на публикацию персональных данных: координаты, календарь и т. п. не коммитить).

### Этап 1. Spike: главный технический риск (дни 2–3) — пройден 2026-11-05

Цель — за минимум кода убедиться, что на One UI работает ключевая связка.

Что уже есть в коде: `StandbyService` (FGS specialUse, runtime receiver зарядки/экрана,
wake-up акселерометр с отчётом раз в 10 с), `StandbyActivity` (часы, яркость 0.01, выход
тапом и при отключении зарядки), `KeepAliveWorker` (периодический, 15 мин, requiresCharging),
`BootReceiver`, экран диагностики `SettingsActivity` (статусы разрешений, переходы в
настройки, кнопка «показать режим через 10 с», журнал `DiagLog` прямо на телефоне).
Для тестов через adb в debug-сборке есть `DebugCommandReceiver` (только `src/debug`, закрыт
правом `DUMP`): `adb shell am broadcast -p com.realfamousbae.standby.dock -a
com.realfamousbae.standby.dock.debug.<STOP_SERVICE|RUN_KEEP_ALIVE|SHOW_STANDBY>`.
Зарядку можно имитировать: `adb shell dumpsys battery unplug` / `set ac 1`, после теста —
обязательно `dumpsys battery reset`.

**Результаты на S24 Ultra (SM-S928B, Android 17, One UI 9), 2026-11-05:**

| Пункт | Результат |
|---|---|
| 4. Запуск поверх блокировки | ✅ `BAL_ALLOW_SAW_PERMISSION`: фоновый старт разрешён правом «Поверх других окон». Activity показана поверх keyguard за ~0.1 с; при погашенном экране сама включает его (`turnScreenOn`). Проверено на имитации зарядки через `dumpsys battery`; с настоящим кабелем и подставкой — повторить при приёмке |
| 5. Акселерометр при погашенном экране | ⚠️ Wake-up акселерометра нет (только `LSM6DSV Accelerometer Non-wakeup`). Запасной вариант с `PARTIAL_WAKE_LOCK` работает: ~17 Гц, пауза ≤ 66 мс в состоянии `Dozing` (AOD). Есть wake-up `Tilt Detector`, `Significant motion`, `Pick Up Gesture` — возможная оптимизация (см. риски) |
| 6. Яркость и выход | ✅ `screenBrightness = 0.01` применяется (`sbrt=0.01`); `finish()` возвращает экран блокировки |
| 7. Подъём службы | ✅ Убийство процесса → `START_STICKY` поднимает за ~4 с. ✅ `MY_PACKAGE_REPLACED` → `BootReceiver` поднимает. ✅ Воркер из cached-процесса: `Background started FGS: Allowed … SYSTEM_ALLOW_LISTED` — исключение из оптимизации батареи работает, overlay 1×1 и точный будильник не нужны. Нюанс: `cmd jobscheduler run -f` для периодической задачи бесполезен, WorkManager её не выполняет раньше срока; задаче система добавляет ограничение `FLEXIBILITY`, т. е. страховка срабатывает с задержкой |
| 8. Заставка Samsung | ✅ `screensaver_enabled=0`, ключ читается (`settings get secure`) |

**Решение по точке принятия решения:** основной механизм A подтверждён, full-screen intent и
DreamService как запасные пути не нужны.

Не проверено (перенесено в этап 6): «Остановить» в настройках приложения (force-stop) — после
него Android по замыслу не поднимает ничего до ручного открытия приложения, это ограничение
платформы, а не наше; сутки простоя; реальный кабель/беспроводная зарядка.

1. Пустая `StandbyActivity` (чёрный экран с часами) с `showWhenLocked/turnScreenOn/keepScreenOn`.
2. `StandbyService` (FGS specialUse), который по `ACTION_POWER_CONNECTED` (runtime
   receiver) через 2 с вызывает `startActivity` с `FLAG_ACTIVITY_NEW_TASK`.
3. Выдать «Поверх других окон» и исключение из батареи.
4. Проверить: экран погашен → подключаем зарядку → Activity появляется поверх
   блокировки. В logcat не должно быть `Background activity launch blocked`.
5. Проверить, что wake-up акселерометр доставляет события при погашенном экране;
   если нет — вариант с `PARTIAL_WAKE_LOCK`.
6. Проверить `screenBrightness` на минимуме и возврат на экран блокировки после `finish()`.
7. Убить процесс сервиса (`adb shell am kill` / «Остановить» в настройках), подключить
   зарядку → `KeepAliveWorker` должен поднять FGS без `ForegroundServiceStartNotAllowedException`.
   Если нет — реализовать запасной маршрут из п. 2.4 (overlay 1×1 или точный будильник).
8. Убедиться, что системная «Заставка» Samsung (Настройки → Дисплей → Заставка)
   выключена, иначе она стартует при засыпании на зарядке и конкурирует с нашей
   Activity. В мастер разрешений добавить проверку `Settings.Secure` (`screensaver_enabled`)
   и подсказку выставить «Никогда»; когда появится собственный DreamService, конфликт
   исчезнет сам (наше приложение и станет заставкой).

**Точка принятия решения.** Если фоновый запуск блокируется на этой версии One UI:
запасной путь — уведомление с full-screen intent (`USE_FULL_SCREEN_INTENT`, для
sideload включается в настройках приложения) или DreamService. Решение фиксируется в
`PLAN.md`.

### Этап 2. Триггер и сервис (дни 4–5)

- `TriggerEngine` как чистая функция состояния: входы (charging, gravity, screenState,
  locked, snoozed, settings) → выход (`Show`/`Hide`), с дебаунсом и гистерезисом.
  Unit-тесты на таблицу сценариев (повернули, положили плашмя, отключили зарядку,
  смотрят видео в ландшафте и т. д.).
- `StandbyService`: подписка на сенсоры только пока заряжается; runtime receivers
  (`POWER_CONNECTED/DISCONNECTED`, `SCREEN_ON/OFF`, `USER_PRESENT`); запуск/закрытие Activity.
- `BootReceiver`, `KeepAliveWorker`, плитка ручного запуска (для отладки и как
  постоянная фича).
- Находки spike, которые этап 2 обязан закрыть:
  - Режим остаётся на экране после разблокировки: в spike он закрылся только при отключении
    зарядки. `TriggerEngine` должен выдавать `Hide` по `USER_PRESENT` / снятию keyguard,
    иначе условие 3 из п. 2.3 действует только на вход. Добавить сценарий в тесты.
  - `PARTIAL_WAKE_LOCK` взят с таймаутом 12 ч: если телефон стоит на зарядке дольше
    (выходные), поток датчика молча перестанет будить процессор. Привязать wake lock к
    времени жизни коллектора датчика (без таймаута, но с гарантированным release) или
    периодически перевзводить.

| One UI блокирует запуск Activity из фона | Spike на этапе 1; `SYSTEM_ALERT_WINDOW` — официальное исключение; запасные пути: full-screen intent, DreamService |
| Samsung убивает сервис через 1–3 дня | «Без ограничений» + «Никогда не усыплять», исключение из оптимизации батареи, периодический `KeepAliveWorker`, рестарт на boot |
| Без зарядки режим разряжает батарею | Порог заряда (по умолчанию 20 %); датчик и wake lock только на время окна пробы 10 с; при показе — минимальная яркость в темноте |
| `Tilt Detector` (скрытый тип 22) может не отдавать события стороннему приложению | Тогда работает только вход «экран погас» и «подключили зарядку»; пишем в журнал при старте службы |
| Без зарядки телефон лежит на боку в сумке/кармане → экран включится там | Проверить на практике. Мера: для входа без зарядки дополнительно требовать «не в кармане» (wake-up датчик `Pocket mode` на S24 Ultra или датчик приближения/света) |
| `Tilt Detector` срабатывает при каждом заметном повороте — при ходьбе частые пробы по 10 с с wake lock | Посмотреть расход в «Батарее» через сутки; мера — ограничить частоту `MotionWake` (например, не чаще раза в минуту) |
| Проверки через adb больше недоступны | Логика решений — в `:core` под unit-тестами; на телефоне — журнал на экране диагностики |
| Ключ подписи потерян | Без него обновить установленное приложение нельзя (только удалить и поставить заново). Ключ и пароль хранятся вне репозитория, пароль — в менеджере паролей пользователя |
| Android 15: FGS из фона требует видимого overlay или исключения из батареи | Запрашиваем исключение из оптимизации батареи; проверяем рестарт в spike; запасные пути: overlay 1×1, точный будильник |
| Системная «Заставка» Samsung конкурирует с режимом | Проверка в мастере разрешений, подсказка выставить «Никогда»; позже свой DreamService |
| Акселерометр молчит при спящем процессоре | Подтверждено: wake-up варианта на S24 Ultra нет. Используем partial wake lock только на зарядке (работает). Оптимизация на потом: будить процессор wake-up датчиками `Tilt Detector`/`Significant motion` и только тогда читать акселерометр |
| Ужесточение фонового аудио в Android 17 (target 37) для кнопок play/pause | Проверить на этапе 4; `MediaController.transportControls` действует на сессию другого приложения, ожидаем, что ограничение не сработает |
| Страховочный воркер срабатывает с задержкой (`FLEXIBILITY`, период 15 мин) | Основной путь — живая служба с `START_STICKY` и runtime receiver; воркер только страховка |
| Выгорание OLED | п. 2.6: чёрный фон, сдвиг, низкая яркость, авто-выключение |
| Тап «выйти» и сразу кнопка питания — режим вернётся через 1.5 с | Отличить кнопку от таймаута системно нельзя; эвристики по таймауту блокировки хрупкие. Принято как известный край |
| Доступ к уведомлениям для APK не из магазина заблокирован («ограниченные настройки», Android 13+) | Подсказка в настройках: Карточка приложения → ⋮ → «Разрешить ограниченные настройки» |
| Системная настройка «содержимое на экране блокировки» не читается на прошивке | Тогда текст в баннере скрыт (только приложение); в журнал пишется, читается ли |
| Виджеты со светлым фоном слепят ночью на OLED | Пока принимаем; позже — затемнение/красный фильтр поверх `AppWidgetHostView` |
| Часть виджетов Samsung не даёт привязку стороннему хосту или требует свой лаунчер | Ошибка видна в журнале; выбрать другой виджет |
| Клик по виджету открывает приложение поверх блокировки | Система просит разблокировку; режим закрывается и вернётся после погасания экрана |
| Ложные срабатывания (видео в ландшафте на зарядке) | вход только по погасанию экрана, дебаунс 1.5 с, запрет после выхода пользователем |
| Погода требует сеть и координаты | координаты вручную как вариант без геолокации; без сети виджет показывает кэш/прочерк |
| One UI может не уважать `showPeeking(false)` своего правила или пользователь выключит режим «StandBy» в Modes | Проверка на телефоне; отказы и включение/выключение видны в журнале («Тихий режим: …») |
| Процесс убит, пока режим показан, — правило «StandBy» остаётся активным (тишина) | При старте службы правило принудительно выключается; служба поднимается `START_STICKY`/воркером |
| Пользователь сам включит «скрывать всплывающие» в общей настройке, пока режим на экране, — при выходе мы его снимем | Принято: снимаем, только если добавляли сами; окно — время показа режима |
| На прошивках с Modes (Android 15+, флаг `modes_api`) `setNotificationPolicy` меняет неявное правило приложения, а не общую политику | Там работает `ZenPolicy` самого правила; по журналу видно, что сработало |
| Нет доступа к «Не беспокоить» | Строка статуса в разделе «Уведомления» с переходом в системные настройки; без доступа режим работает как раньше |
| Персональные данные в репозитории | координаты, календари, ключи подписи — только в локальных настройках/`local.properties`, в `.gitignore` |

## 7. Проверка результата (приёмочный чек-лист)

1. Без зарядки: попользовались, поставили на подставку, погасили экран кнопкой (и отдельно —
   дождались таймаута) → через ~1.5 с режим. С зарядкой: погашенный телефон ставим на
   подставку и подключаем зарядку → режим.
2. Снимаем с подставки в портрет → режим закрывается, видна блокировка. Без зарядки при
   заряде ниже порога режим не включается.
2а. Тап «выйти» на подставке → после погасания экрана режим не возвращается; сняли и
   поставили снова → работает.
2б. Свет в комнате выключили → яркость плавно падает до минимума.
3. Телефон разблокирован, смотрим видео в ландшафте на зарядке → режим не появляется.
4. Лежит плашмя экраном вверх на беспроводной зарядке → режим не появляется.
5. Ночь по расписанию / темно по датчику / ручной тумблер → красная палитра, яркость
   минимальная; все шесть вариантов режима ведут себя по настройке.
6. Каждый виджет показывает данные, а без разрешения — подсказку.
7. После перезагрузки и после суток без запуска приложения сценарий 1 работает.
8. Unit-тесты `TriggerEngine`, `NightModeDecider`, `SolarTimes` зелёные.
9. В logcat за сутки нет `Background activity launch blocked` и крашей сервиса.
